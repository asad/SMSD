    Screening a library¶

    Screening narrows a library down to the molecules worth a closer look. SMSD Pro offers these routes: a ranked list for a handful of molecules, a fingerprint threshold screen held in memory or streamed from a file, a saved packed index, an exact substructure screen and an MCS-similarity screen. This chapter shows which route suits which task, how to prepare the library, how to run each screen and how to save the hits. Every example uses the same inline library of 533 molecules: 14 benzodiazepines, 7 common drugs and 512 generated trisubstituted benzenes, so each program runs as it stands, with no data files.

    Choose a route¶

    Task Use Fingerprint Prepare first Needs NumPy GPU
    Rank a small list batch_similarity ECFP; radius 2 and 2048 bits by default Nothing No No
    Threshold screen in memory TargetCorpus.screen or screen_many ECFP radius 2, 2048 bits, fixed prewarm() after every addition No With smsd-cuda, automatic on a Tesla T4 for 100,000 targets or more, or on any supported device from SMSD_CUDA_MIN_TARGETS targets; see the device rule
    Screen a large file once stream_screen_smiles or stream_screen_many_smiles ECFP radius 2, 2048 bits, fixed Nothing No As above, chunk by chunk
    Search a saved index many times FingerprintCorpus; see the packed index Any binary specification Build the file once Yes On request, with backend="cuda" or "auto"
    Exact substructure Substructure.match_corpus None: exact search A TargetCorpus No Optional pre-screen, with gpu_prefilter=True
    MCS similarity screen_targets, then MCS.match_many; or MCS.match_corpus None: an atom-count bound, then the exact MCS A list or a TargetCorpus No screen_targets runs on the CPU; MCS.match_corpus takes gpu_prefilter=True

    The in-memory, streamed and packed-index screens give the same hits for the same query and threshold when the index is built with ECFP radius 2 and 2048 bits, because they then compare the same fingerprints. Graph matching always runs on the CPU, and every GPU route returns the same results as the CPU. CPU and GPU screening explains when a device is used.

    Prepare the library¶

    A screen is only as consistent as its input. Four points matter before any corpus is built:

    • Malformed SD records. smsd.read_sdf reads the whole file and returns a malformed record as an empty graph, with no warning. An empty graph still takes part in a screen and passes one with a threshold of 0, so keep only graphs with graph.n > 0.
    • SMILES files. A line that holds a name after the SMILES does not parse as SMILES, so split off the first column. There is no SMILES-file reader; a generator over the lines serves, and keeps memory flat for the streamed screens.
    • Identifiers. A TargetCorpus or FingerprintCorpus stores no names and cannot be indexed or iterated. Keep the names in a list in the same order; every hit index refers to that list.
    • Hydrogens. Explicit hydrogens are graph atoms, so a record written with them has quite different fingerprints from the same molecule without them. Write or export every record in the same form, with implicit hydrogens.

    The program below defines the library, writes it as an SD file with a title and a SOURCE field per record and as a SMILES file with SMILES name lines, adds a malformed record, then reads both files back:

    import itertools
from pathlib import Path
from tempfile import TemporaryDirectory

import smsd

NAMED = {
    "diazepam": "CN1C(=O)CN=C(c2ccccc2)c2cc(Cl)ccc21",
    "nordazepam": "O=C1CN=C(c2ccccc2)c2cc(Cl)ccc2N1",
    "temazepam": "CN1C(=O)C(O)N=C(c2ccccc2)c2cc(Cl)ccc21",
    "oxazepam": "OC1N=C(c2ccccc2)c2cc(Cl)ccc2NC1=O",
    "lorazepam": "OC1N=C(c2ccccc2Cl)c2cc(Cl)ccc2NC1=O",
    "clonazepam": "O=C1CN=C(c2ccccc2Cl)c2cc([N+](=O)[O-])ccc2N1",
    "nitrazepam": "O=C1CN=C(c2ccccc2)c2cc([N+](=O)[O-])ccc2N1",
    "flunitrazepam": "CN1C(=O)CN=C(c2ccccc2F)c2cc([N+](=O)[O-])ccc21",
    "bromazepam": "O=C1CN=C(c2ccccn2)c2cc(Br)ccc2N1",
    "tetrazepam": "CN1C(=O)CN=C(C2=CCCCC2)c2cc(Cl)ccc21",
    "alprazolam": "Cc1nnc2n1-c1ccc(Cl)cc1C(c1ccccc1)=NC2",
    "triazolam": "Cc1nnc2n1-c1ccc(Cl)cc1C(c1ccccc1Cl)=NC2",
    "midazolam": "Cc1ncc2n1-c1ccc(Cl)cc1C(c1ccccc1F)=NC2",
    "clobazam": "CN1C(=O)CC(=O)N(c2ccccc2)c2cc(Cl)ccc21",
    "aspirin": "CC(=O)Oc1ccccc1C(=O)O",
    "salicylic acid": "OC(=O)c1ccccc1O",
    "paracetamol": "CC(=O)Nc1ccc(O)cc1",
    "ibuprofen": "CC(C)Cc1ccc(cc1)C(C)C(=O)O",
    "naproxen": "COc1ccc2cc(ccc2c1)C(C)C(=O)O",
    "caffeine": "CN1C=NC2=C1C(=O)N(C(=O)N2C)C",
    "phenol": "Oc1ccccc1",
}
GROUPS = ["C", "CC", "OC", "N", "O", "F", "Cl", "C(=O)O"]
library = list(NAMED.items()) + [
    (f"GEN-{number:03d}", f"c1c({a})cc({b})cc1{c}")
    for number, (a, b, c) in enumerate(itertools.product(GROUPS, repeat=3))
]
names = [name for name, _ in library]
smiles = [text for _, text in library]
assert len(library) == 533

with TemporaryDirectory() as directory:
    sdf_path = Path(directory) / "library.sdf"
    smi_path = Path(directory) / "library.smi"

    # Write an SD file with a title and a SOURCE field per record ...
    graphs = []
    for name, text in library:
        graph = smsd.parse_smiles(text)
        graph.name = name
        graph.properties = {"SOURCE": "named" if name in NAMED else "generated"}
        graphs.append(graph)
    smsd.write_sdf(graphs, sdf_path)
    with sdf_path.open("a", encoding="utf-8") as stream:
        stream.write("garbage\nnot a molfile\n\nM  END\n$$$$\n")  # malformed
    # ... and a SMILES file with "SMILES name" lines.
    smi_path.write_text("".join(f"{text} {name}\n" for name, text in library),
                        encoding="utf-8")

    # A malformed SD record comes back as an empty graph: drop it.
    records = smsd.read_sdf(sdf_path)
    kept = [graph for graph in records if graph.n > 0]
    print("SD records:", len(records), "| with atoms:", len(kept))
    print("first record:", kept[0].name, dict(kept[0].properties))

    # A SMILES line holds the SMILES first; the rest of the line is the name.
    lines = smi_path.read_text(encoding="utf-8").splitlines()
    rows = [line.split(maxsplit=1) for line in lines if line.strip()]
    file_smiles = [row[0] for row in rows]
    file_names = [row[1] if len(row) > 1 else "" for row in rows]
    print("SMILES lines:", len(rows), "| a name with a space:", file_names[15])

assert len(records) == 534 and len(kept) == 533
assert [graph.name for graph in kept] == names == file_names
assert dict(kept[0].properties) == {"SOURCE": "named"}
assert file_smiles == smiles

    SD records: 534 | with atoms: 533

    Duplicates are common in assembled libraries. smsd.canonical_hash groups candidate duplicates quickly, but a hash is a screening key rather than proof of identity, so confirm each candidate with smsd.same_canonical_graph. The generated benzenes carry their three substituents in equivalent positions, so the 512 SMILES describe only 120 distinct structures, and the whole library holds 141:

    "salicylic acid": "OC(=O)c1ccccc1O",

    "ibuprofen": "CC(C)Cc1ccc(cc1)C(C)C(=O)O",
    "naproxen": "COc1ccc2cc(ccc2c1)C(C)C(=O)O",
    "caffeine": "CN1C=NC2=C1C(=O)N(C(=O)N2C)C",
    "phenol": "Oc1ccccc1",
}
GROUPS = ["C", "CC", "OC", "N", "O", "F", "Cl", "C(=O)O"]

    (f"GEN-{number:03d}", f"c1c({a})cc({b})cc1{c}")
    for number, (a, b, c) in enumerate(itertools.product(GROUPS, repeat=3))
]
names = [name for name, _ in library]
smiles = [text for _, text in library]
assert len(library) == 533

# Group records by canonical hash, then confirm each candidate with a graph
# comparison, because a hash alone is not proof of identity.
graphs = [smsd.parse_smiles(text) for text in smiles]
seen = {}
unique, repeats = [], []
for index, graph in enumerate(graphs):
    bucket = seen.setdefault(smsd.canonical_hash(graph), [])
    same = [kept for kept in bucket
            if smsd.same_canonical_graph(graphs[kept], graph)]
    if same:
        repeats.append((index, same[0]))
    else:
        bucket.append(index)
        unique.append(index)
print("records:", len(graphs), "| distinct structures:", len(unique))
print("first repeat:", names[repeats[0][0]], "is", names[repeats[0][1]])
assert len(unique) == 141 and len(repeats) == 392
assert [names[i] for i in repeats[0]] == ["GEN-008", "GEN-001"]

# Explicit hydrogens are graph atoms, so they change every fingerprint.
plain = smsd.parse_smiles(NAMED["paracetamol"])
explicit = smsd.parse_smiles(  # paracetamol with explicit hydrogens
    "[H]Oc1c([H])c([H])c(N([H])C(=O)C([H])([H])[H])c([H])c1[H]")
score = smsd.tanimoto_coefficient(smsd.fingerprint(plain, kind="ecfp"),
                                  smsd.fingerprint(explicit, kind="ecfp"))
print("paracetamol atoms:", plain.n, "and", explicit.n,
      "| ECFP4 Tanimoto:", f"{score:.3f}")
assert (plain.n, explicit.n) == (11, 20)
assert f"{score:.3f}" == "0.018"

    records: 533 | distinct structures: 141

    The same paracetamol with and without explicit hydrogens shares almost no ECFP bits, which is why a library should be consistent before it is screened.

    Similarity screen in memory¶

    TargetCorpus.from_smiles parses the library once and keeps it in memory. prewarm() computes an ECFP radius 2, 2048-bit fingerprint for every target; screen and screen_many then compare one or more queries with them and return the indices of the targets whose Tanimoto score is at least the threshold, in library order. They return indices only. For scores, use batch_similarity on the hits, as in Save the hits, or a packed index.

    A screen run before prewarm(), or after any target is added, returns an empty list rather than raising, so call prewarm() again after every addition. smsd.warm_start(corpus, query, threshold) prepares the corpus when it needs it and then screens.

    import itertools

import smsd

NAMED = {
    "diazepam": "CN1C(=O)CN=C(c2ccccc2)c2cc(Cl)ccc21",
    "nordazepam": "O=C1CN=C(c2ccccc2)c2cc(Cl)ccc2N1",
    "temazepam": "CN1C(=O)C(O)N=C(c2ccccc2)c2cc(Cl)ccc21",
    "oxazepam": "OC1N=C(c2ccccc2)c2cc(Cl)ccc2NC1=O",
    "lorazepam": "OC1N=C(c2ccccc2Cl)c2cc(Cl)ccc2NC1=O",
    "clonazepam": "O=C1CN=C(c2ccccc2Cl)c2cc([N+](=O)[O-])ccc2N1",

    "flunitrazepam": "CN1C(=O)CN=C(c2ccccc2F)c2cc([N+](=O)[O-])ccc21",

    "clobazam": "CN1C(=O)CC(=O)N(c2ccccc2)c2cc(Cl)ccc21",
    "aspirin": "CC(=O)Oc1ccccc1C(=O)O",
    "salicylic acid": "OC(=O)c1ccccc1O",

    "naproxen": "COc1ccc2cc(ccc2c1)C(C)C(=O)O",

    "phenol": "Oc1ccccc1",

diazepam = NAMED["diazepam"]
alprazolam = NAMED["alprazolam"]

corpus = smsd.TargetCorpus.from_smiles(smiles[:21])  # the named drugs
corpus.prewarm(num_threads=2)
corpus.add_targets(smiles[21:])                      # then the generated set
# An addition clears the preparation, and an unprepared screen finds nothing.
assert not corpus.is_prewarmed
assert corpus.screen(diazepam, 0.5, num_threads=2) == []

corpus.prewarm(num_threads=2)
hits = corpus.screen(diazepam, 0.5, num_threads=2)
print("diazepam, at least 0.5:", [names[i] for i in hits])

per_query = corpus.screen_many([diazepam, alprazolam], 0.5, num_threads=2)
print("alprazolam, at least 0.5:", [names[i] for i in per_query[1]])

# The threshold is inclusive: 1.0 keeps identical fingerprints.
exact = corpus.screen(diazepam, 1.0, num_threads=2)
print("diazepam, at least 1.0:", [names[i] for i in exact])

# warm_start prepares a corpus when needed, then screens it.
fresh = smsd.TargetCorpus.from_smiles(smiles)
assert smsd.warm_start(fresh, diazepam, 0.5, num_threads=2) == hits
assert fresh.is_prewarmed

assert [names[i] for i in hits] == [
    "diazepam", "nordazepam", "temazepam", "tetrazepam", "clobazam"]
assert per_query[0] == hits
assert [names[i] for i in per_query[1]] == [
    "alprazolam", "triazolam", "midazolam"]
assert exact == [0]

    The program prints:

    diazepam, at least 0.5: ['diazepam', 'nordazepam', 'temazepam', 'tetrazepam', 'clobazam']
alprazolam, at least 0.5: ['alprazolam', 'triazolam', 'midazolam']

    screen and screen_many do not check the threshold: a value above 1 or a NaN returns no hits, and a negative value returns every target, so pass a number from 0 to 1. warm_start does check it, but defaults to 0.0, which returns every target; always pass a threshold. Thread counts must be non-negative integers; screen and prewarm do not check this either.

    Streamed similarity screen¶

    A library that is screened once does not need to sit in memory. smsd.stream_screen_smiles(query, targets, threshold) takes any one-shot iterable of molecules, such as a generator over the lines of a file, builds one chunk of targets at a time, screens it with the same fixed ECFP radius 2, 2048-bit fingerprints and yields the input index of each hit, in input order. Only one chunk is held at a time, and NumPy is not needed.

    smsd.stream_screen_many_smiles screens several queries in bounded tiles of queries by targets and yields (query_index, target_index) pairs. The pairs come tile by tile, then by query, then by target: they are neither grouped by query nor ranked, so sort them when order matters.

def smiles_column(path):
    """Yield the first column of a SMILES file, one line at a time."""
    with open(path, encoding="utf-8") as stream:
        for line in stream:
            if line.strip():
                yield line.split()[0]


diazepam = NAMED["diazepam"]
alprazolam = NAMED["alprazolam"]
with TemporaryDirectory() as directory:
    path = Path(directory) / "library.smi"
    path.write_text("".join(f"{text} {name}\n" for name, text in library),
                    encoding="utf-8")

    hits = list(smsd.stream_screen_smiles(
        diazepam, smiles_column(path), 0.5, chunk_size=100, num_threads=2))
    print("diazepam, at least 0.5, input indices:", hits)

        [diazepam, alprazolam], smiles_column(path), 0.5,
        target_chunk_size=4, query_chunk_size=2, num_threads=2))
    print("(query, input index) as streamed:", pairs)
    print("(query, input index) sorted:", sorted(pairs))

    diazepam, at least 0.5, input indices: [0, 1, 2, 9, 13]

An invalid molecule later in the input raises ValueError after the hits of earlier chunks have been yielded, and the message does not name the failing input, so check a doubtful file before a long run.

    Substructure screen with exact confirmation¶

    Substructure.match_corpus(corpus) searches a TargetCorpus and returns one CorpusSearchResult per target, in library order. Targets that cannot contain the query are ruled out before matching, with a proof; every other target is searched exactly on the CPU. The decisions are the same as those of match_many over the whole library, and no prewarm() is needed.

    Field Meaning
    target_index The position of the target in the corpus
    threshold_reached The query was found; result holds the match
    proven_below_threshold The query is proved absent, before matching or by a completed search
    result The SearchResult of the search, or None for a target ruled out before matching
    atom_upper_bound Always None for a substructure search

    When both flags are false the outcome is unknown, for example after a search that stopped at its time limit; that is not proof of absence.

    MCS-similarity screen¶

    MCS similarity here is the atom-count Tanimoto of the maximum common substructure: common / (query atoms + target atoms - common). Computing the MCS for every target is the expensive step, so screen first. smsd.screen_targets(query, targets, threshold) computes a fast upper bound on that score for every target and returns the indices that reach the threshold. Under the same chemistry options it never rejects a target that can reach the threshold. It needs no prewarm(). The bound can keep targets that fall short, so run the exact MCS on the survivors and keep the results that are optimal and reach the threshold.

    MCS.match_corpus(corpus, minimum_atoms) answers a related question for each target: whether the MCS with the query has at least minimum_atoms atoms. It returns the same CorpusSearchResult fields as the substructure screen, with atom_upper_bound holding an upper bound on the MCS atom count where one was computed.

    Options¶

    TargetCorpus¶

    Member Returns Meaning
    TargetCorpus.from_smiles(targets) TargetCorpus Captures SMILES strings, MolGraph objects or RDKit molecules from any iterable
    add_target(target), add_targets(targets) None Adds targets; the corpus then needs prewarm() again
    prewarm(*, num_threads=0) None Computes the screening fingerprints and graph invariants
    is_prewarmed bool Whether prewarm() has run since the last addition
    len(corpus) int The number of targets
    screen(query, threshold, *, num_threads=0) list[int] ECFP radius 2, 2048-bit Tanimoto hits, at least threshold, in target order
    screen_many(queries, threshold, *, num_threads=0) list[list[int]] One hit list per query, in query order
    screen_targets_many(queries, threshold, chemistry=None, *, num_threads=0) list[list[int]] The MCS-similarity bound for each query; no prewarm() needed
    smsd.warm_start(corpus, query, threshold=0.0, *, num_threads=0) list[int] Prepares the corpus if needed, then screens; the threshold is checked

    A TargetCorpus cannot be saved or pickled. num_threads=0 uses the OpenMP default, which OMP_NUM_THREADS sets.

    Streamed screens¶

    stream_screen_smiles(query, targets, threshold, *, chunk_size=4096, num_threads=0) and stream_screen_many_smiles(queries, targets, threshold, *, target_chunk_size=4096, query_chunk_size=64, max_queries=4096, num_threads=0) take these arguments:

    Name Type Default Meaning
    query, queries molecule, iterable of molecules required SMILES strings, MolGraph objects or RDKit molecules
    targets iterable required Read once; a generator is suitable
    threshold float required Inclusive; finite and from 0 to 1, otherwise ValueError
    chunk_size int 4096 Targets per chunk; values above 1,048,576 are reduced to 1,048,576
    target_chunk_size int 4096 Targets per tile, from 1 to 1,048,576
    query_chunk_size int 64 Queries per tile, from 1 to 1,048,576; a tile may hold at most 1,048,576 query and target pairs
    max_queries int 4096 Most queries accepted, from 1 to 1,048,576; more raise ValueError
    num_threads int 0 Threads per chunk; 0 uses the OpenMP default

    With no queries, stream_screen_many_smiles yields nothing and does not read the targets.

    screen_targets¶

    smsd.screen_targets(query, targets, threshold, chemistry=None, *, num_threads=0) returns the indices of the targets whose bound reaches the threshold, in target order.

    Name Type Default Meaning
    query molecule required SMILES string, MolGraph or RDKit molecule
    targets list or TargetCorpus required A TargetCorpus is converted once and reused
    threshold float required Inclusive atom-count Tanimoto threshold; not checked
    chemistry ChemOptions or None None None means ChemOptions(); use the options of the exact search
    num_threads int 0 Non-negative; 0 uses the OpenMP default

    batch_similarity¶

    smsd.batch_similarity(query, targets, fp_size=2048, radius=2) returns (index, Tanimoto) pairs, most similar first; equal scores keep their input order.

    Name Type Default Meaning
    query molecule required SMILES string or MolGraph
    targets list required Every target is fingerprinted on each call, so keep the list small
    fp_size int 2048 Fingerprint width in bits
    radius int 2 ECFP radius

    Notes¶

    • Hits do not depend on the thread count or the chunk sizes. Only the order of the pairs from stream_screen_many_smiles and FingerprintCorpus.screen_many depends on the tile sizes.
    • smsd.similarity(a, b) is the MCS-similarity bound of screen_targets, the same value as smsd.similarity_upper_bound, not a fingerprint score.
    • smsd.prewarm(mol) caches the invariants of a molecule that is searched many times, such as a query run against several libraries.
    • A parse error in TargetCorpus.from_smiles, the streamed screens or FingerprintCorpus.from_smiles does not name the failing input.
    • smsd.to_smiles raises ValueError for the few stereo records it cannot write; keep those records in SD form. smsd.canonical_smiles is a deprecated alias of smsd.to_smiles.
    • A substructure or MCS screen needs the whole TargetCorpus in memory; only the fingerprint screens stream.
    • Speed depends on the data, the hardware and the thread count. Time a representative sample on your own machine, and compare the results as well as the times.
