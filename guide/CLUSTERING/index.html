    Clustering and diversity¶

    Clustering and diverse selection turn a library into something a chemist can review: a set of series, each led by a representative, or a short list of molecules that cover the library's chemistry. SMSD Pro offers three exact tools on a packed fingerprint index: smsd.butina groups rows around cluster centres, smsd.maxmin picks a fixed number of diverse rows, and FingerprintCorpus.top_k_pairs finds the nearest neighbours of every row. This chapter shows which to use for which task, how the threshold, reordering, seed and chunk size behave, what each costs in time and memory, and what runs on a GPU. Every example uses the inline library of Screening a library: 14 benzodiazepines, 7 common drugs and 512 generated trisubstituted benzenes.

    All three tools read a FingerprintCorpus, so they need NumPy, from the numpy extra:

    python -m pip install "smsd[numpy]==8.1.0"

    Choose a method¶

    Task Use Returns Comparison work for n rows Extra memory
    Group a library into series, each with a representative smsd.butina(corpus, threshold) A list of tuples, centre first About n²/2, plus one pass over the library per cluster; reordering=True adds about n² Two arrays of n entries, about 9 bytes per row
    Pick a fixed number of diverse rows smsd.maxmin(corpus, count, seed=0) A list of rows in the order picked n for each row picked One array of n entries, 8 bytes per row
    Find the k nearest neighbours of every row, near-duplicates or outliers corpus.top_k_pairs(k, threshold=0.0) Yields (row, neighbour, Tanimoto), at most k per row, best first About n² k entries per row in progress; n × k if every result is kept
    List every pair above a similarity corpus.threshold_pairs(threshold) Yields (first, second, Tanimoto), each pair once About n²/2 Up to n²/2 pairs if every result is kept

    Some guidance on the choice:

    • Use Butina when the question is "which series does this library contain?". The number of clusters follows from the threshold, not from a target count.
    • Use MaxMin when the question is "which N molecules should we buy, test or inspect first?". The count is fixed and the threshold is implicit.
    • Use top_k_pairs to inspect a library before clustering it: identical fingerprints, close analogues and molecules with no near neighbour all show up in its output.
    • Every method compares fingerprints exactly; none samples the library or approximates a score. The work therefore grows with the square of the row count, or with the row count times the number picked for MaxMin, and the results are the same on every run, every chunk size and every backend.

    Prepare the input¶

    The three tools take an open FingerprintCorpus, built once with FingerprintCorpus.from_smiles or FingerprintCorpus.create, as Packed fingerprint index describes. Four points matter before clustering:

    • The fingerprint decides the answer. A cluster threshold of 0.5 on ECFP4 bits is a different statement from 0.5 on path bits. The index file records the width and row count but not the options, so keep the FingerprintOptions beside it and state them with every result.
    • Rows are numbers. The index stores no names, and every returned row refers to the input order. Keep the identifiers in a list in the same order.
    • Duplicates are counted. Identical fingerprints score 1 with each other, so a series entered many times has many neighbours and tends to supply the first and largest clusters. Remove duplicate structures first if the counts matter; see Prepare the library.
    • Empty fingerprints score 1 with each other. Empty graphs from malformed SD records therefore fall into one cluster, and they score 0 against every other row. Drop graphs with no atoms before building the index.

    Cluster a library with Butina¶

    smsd.butina(corpus, threshold=0.7) counts, for every row, the other rows whose Tanimoto similarity is at least the threshold. The row with the most neighbours becomes the first centre and takes all its unassigned neighbours as members; the next centre is the unassigned row with the most neighbours, and so on until every row is assigned. Equal counts go to the lower row. The result is a list of tuples, each with its centre first and the other members in row order, and every row appears in exactly one tuple.

    A member reaches the threshold with its centre, but not necessarily with the other members of its cluster. A row also joins the first cluster whose centre reaches it, even when a later centre would be closer. The program below clusters the whole library at 0.5 and checks both properties:

    import itertools

                                            options=options) as corpus:

nordazepam, bromazepam = names.index("nordazepam"), names.index("bromazepam")
score = smsd.tanimoto_coefficient(fingerprints[nordazepam],

    Thresholds and reordering¶

    The threshold is a Tanimoto similarity, inclusive, from 0 to 1; a higher threshold gives more, tighter clusters. With the default reordering=False the neighbour counts are computed once, before any cluster is taken, so a later centre may be chosen for neighbours that earlier clusters have already claimed. reordering=True recounts after each cluster so that only unassigned neighbours count, and later centres are chosen by the neighbours still available. It costs up to about three times the comparisons. Neither mode is more exact than the other; they answer slightly different questions, so record which one a result used.

    Pick a diverse subset with MaxMin¶

    smsd.maxmin(corpus, count, seed=0) starts at row seed, then repeatedly takes the row whose closest already-picked row is the least similar, that is, the row with the largest minimum Tanimoto distance (1 − Tanimoto) to the selection. Equal distances go to the lower row, and no random numbers are used, so the same index, count and seed always give the same list. The list is in the order picked, and a shorter run is a prefix of a longer one: the first three rows of a pick of eight are exactly the pick of three.

    The seed decides where the selection starts. Row 0 is the default, which makes the result depend on the input order. Choose a seed that means something, such as a reference compound or the centre of the largest Butina cluster, and record it.

def closest_pair(fingerprints, rows):
    """The highest Tanimoto similarity between any two of the given rows."""
    return max(smsd.tanimoto_coefficient(fingerprints[a], fingerprints[b])
               for a, b in itertools.combinations(rows, 2))


options = smsd.FingerprintOptions.ecfp(radius=2, size=2048)
with TemporaryDirectory() as directory:
    path = Path(directory) / "library.fp"
    with smsd.FingerprintCorpus.from_smiles(path, smiles,
                                            options=options) as corpus:
        first = smsd.maxmin(corpus, 8)  # starts at row 0, diazepam
        phenol = smsd.maxmin(corpus, 8, seed=names.index("phenol"))
        assert smsd.maxmin(corpus, 3) == first[:3]  # a prefix of the longer pick
        assert smsd.maxmin(corpus, 0) == []
        fingerprints = [corpus.fingerprint(row) for row in range(len(corpus))]

print("from diazepam:", [names[row] for row in first])
print("from phenol:  ", [names[row] for row in phenol])
print(f"closest pair in the first pick: {closest_pair(fingerprints, first):.3f}")
print(f"closest pair in rows 0 to 7:    "
      f"{closest_pair(fingerprints, range(8)):.3f}")
assert [names[row] for row in first[:3]] == ["diazepam", "GEN-148", "caffeine"]
assert phenol[0] == names.index("phenol") and len(set(phenol)) == 8

    from diazepam: ['diazepam', 'GEN-148', 'caffeine', 'GEN-175', 'paracetamol', 'GEN-219', 'naproxen', 'GEN-294']

    Eight rows picked by MaxMin share at most 0.113 with each other, whereas the first eight rows of the file, all benzodiazepines, include a pair at 0.755. Two seeds give different selections of similar quality, which is expected: MaxMin is a greedy pick, not a search for the most diverse subset of a given size. count may be any number from 0 to the row count; a seed past the last row raises IndexError, and a negative one ValueError.

    MaxMin favours the edges of the library: its first picks are the molecules least like everything already chosen, which often includes outliers and oddities. To cover the populated regions instead, cluster first and take the Butina centres, or run MaxMin on an index built from the centres.

    Nearest neighbours and pairs¶

    corpus.top_k_pairs(k, threshold=0.0) yields the k most similar other rows of every row as (row, neighbour, Tanimoto). The output is grouped by row in row order, best first within each row, and equal scores prefer the lower neighbour. threshold drops neighbours below it, so a row with no neighbour at or above the threshold yields nothing: that is a direct way to find outliers. include_self=False leaves out each row's pairing with itself, and k is reduced to the number of other rows when it is larger. The method is a generator, so consume it as it streams when the library is large.

    print(f"{names[row]:<11} -> {names[neighbour]:<11} {score:.3f}")
print("rows with an identical twin:", twins)
print("rows with no neighbour at 0.4:",
      [names[row] for row in range(len(names)) if row not in close])
assert len(nearest) == 6 and twins == 504 and len(close) == 526

Both findings are worth having before clustering: the first says the counts behind Butina centres are inflated by duplicates, and the second says which rows will end up as singletons at 0.4 or above.

    top_k_pairs reports each relationship from both sides, as two directed pairs. When every pair above a similarity is wanted once, use corpus.threshold_pairs(threshold), which yields (first, second, Tanimoto) with first < second; Neighbours and pairs within the index shows it.

    Chunk size, determinism and cost¶

    chunk_size sets how many rows are compared at a time. It changes the working memory, never the clusters, selections or neighbours. The default of 4096 rows is reduced automatically to keep each chunk's working arrays within about 64 MiB, so it rarely needs changing; lower it only to cut peak memory on a small machine. Results do not depend on the chunk size, the backend or the run, because every score is computed exactly and every tie goes to the lower row.

    The comparison work is what limits library size:

    • Butina compares every pair once to count neighbours, about n²/2 comparisons, then makes one pass over the library for each cluster it forms. With reordering=True it also makes a pass for every row it assigns, which adds about n² comparisons. Doubling the library roughly quadruples the time.
    • MaxMin makes one pass over the library for each row it picks, n × count comparisons, so it grows linearly with the library for a fixed count.
    • top_k_pairs compares every row with every other row, about n² comparisons, because each row is ranked against the whole library.

    Memory stays modest. Butina keeps two arrays of n entries, about 9 bytes per row, and MaxMin one array of 8 bytes per row; neither builds a similarity matrix or a neighbour list. The index file is memory-mapped, at ceil(fp_size / 8) bytes per row: 256 bytes for 2048 bits. The returned clusters and any pairs you keep are ordinary Python objects and come on top; collecting all of top_k_pairs needs n × k results, and all of threshold_pairs can need memory that grows with n². Time a representative sample on your own hardware before committing to a library size, as the notes of Screening a library advise.

    CPU and GPU backends¶

    smsd.butina, smsd.maxmin, top_k_pairs and threshold_pairs take the same backend argument as the other searches of a packed index:

    Backend Behaviour
    "cpu" The default. NumPy compares the packed rows on the CPU; the CUDA package is not loaded.
    "cuda" The comparisons run on an NVIDIA GPU. It needs the smsd-cuda package of the same version, a usable device and a little-endian host, and raises RuntimeError otherwise; fingerprints wider than 65,536 bits raise ValueError.
    "auto" Uses the GPU under the same conditions, for an index of any size, and the CPU otherwise.

    The GPU takes only the fingerprint comparisons; the decisions stay on the CPU:

    Call On the GPU On the CPU
    butina Exact integer intersection counts of one row against a tile of rows Tanimoto scores from those counts, threshold tests, neighbour counts, centre choice, membership and recounting
    maxmin Exact integer intersection counts of the last picked row against a tile of rows Tanimoto distances, minimum-distance updates and the choice of the next row
    top_k_pairs Intersection counts, the threshold test and the best k of each tile Tanimoto scores from those counts, and the merge of the tile lists into the final k with the same score and row-order tie break
    threshold_pairs Exact integer intersection counts Tanimoto scores and the inclusive threshold test

    Both devices form each score from the same integer counts with the same double-precision division, and every tie is broken on the CPU by row order. The clusters, selections, neighbours and scores are therefore identical on either device; the GPU does not make any of these methods approximate. Each device call covers one tile of at most 1,048,576 row pairs, and a 64 MiB host-work estimate can make a tile smaller than chunk_size. The rows of a tile are sent to the device for that call and released afterwards, so the index is not kept on the GPU between calls, and a Butina run sends the library once for every pass it makes.

    corpus.cuda_calls is the cumulative number of packed CUDA calls that the corpus has completed, clustering passes included. Read it before and after a call: an increase proves that the device did work for that call. It is not a count of queries, hits or kernels, and it says nothing about speed. Under "auto", the CPU is used only when the CUDA package or a device is unavailable, or the width is unsupported; once device work has started, an error is raised rather than the call being retried on the CPU. Setting SMSD_DISABLE_GPU to any value other than 0 keeps these calls on the CPU, and on a Mac they always run on the CPU.

    The program below runs on any machine. It checks that the chunk size and the "auto" backend leave every result unchanged, and, where backend="cuda" can run, that the GPU gives the same results:

def cuda_usable():
    """Whether backend="cuda" can run here."""
    return (smsd_cuda is not None and sys.byteorder == "little"
            and os.environ.get("SMSD_DISABLE_GPU", "") in ("", "0")
            and smsd_cuda.__version__ == smsd.__version__
            and smsd_cuda.is_available())


def results(corpus, **controls):
    """Butina clusters, a MaxMin pick and the two nearest neighbours of each row."""
    return (smsd.butina(corpus, threshold=0.5, **controls),
            smsd.maxmin(corpus, 8, **controls),
            list(corpus.top_k_pairs(2, **controls)))

            assert corpus.cuda_calls > before  # the device did the comparisons

    Options¶

    smsd.butina¶

    smsd.butina(corpus, threshold=0.7, *, reordering=False, chunk_size=4096, backend="cpu") returns a list of tuples of row indices, each with its centre first and its other members in row order.

    Name Type Default Meaning
    corpus FingerprintCorpus required An open packed index; anything else raises TypeError, a closed one ValueError
    threshold float 0.7 Inclusive Tanimoto similarity a member must reach with its centre; finite and from 0 to 1
    reordering bool False True recounts unassigned neighbours after each cluster; must be a bool
    chunk_size int 4096 Rows compared at a time; at least 1, reduced to keep each chunk within about 64 MiB
    backend str "cpu" "cpu", "cuda" or "auto"; any other value raises ValueError

    smsd.maxmin¶

    smsd.maxmin(corpus, count, *, seed=0, chunk_size=4096, backend="cpu") returns a list of count distinct row indices in the order picked.

    Name Type Default Meaning
    corpus FingerprintCorpus required An open packed index
    count int required Rows to pick, from 0 to the row count; outside that range raises ValueError
    seed int 0 The first row picked; a row past the last raises IndexError, a negative one ValueError
    chunk_size int 4096 As for butina
    backend str "cpu" As for butina

    FingerprintCorpus.top_k_pairs¶

    corpus.top_k_pairs(k, *, threshold=0.0, include_self=False, chunk_size=4096, backend="cpu") yields (row, neighbour, Tanimoto) tuples.

    Name Type Default Meaning
    k int required Neighbours per row, at least 0; reduced to the number of candidate rows; 0 yields nothing
    threshold float 0.0 Inclusive lower bound on the reported Tanimoto similarity
    include_self bool False True lets a row be its own neighbour, with a score of 1
    chunk_size int 4096 As for butina
    backend str "cpu" As for butina; with "cuda" or "auto", a loaded CUDA package must also provide its top-k operation, or RuntimeError is raised

    Integer arguments reject booleans and floats with TypeError. A threshold outside 0 to 1, or one that is not finite, raises ValueError.

    Notes¶

    • A Butina cluster is defined by its centre. Two members of one cluster can be less similar to each other than the threshold, and a row joins the first cluster whose centre reaches it, not necessarily the closest centre.
    • Butina centres depend on the neighbour counts, so duplicates and the choice of reordering change them. Apart from the row that seed=0 names, changing the row order changes only how equal counts and equal distances are resolved.
    • MaxMin is greedy. It gives a well-spread selection quickly, but a different seed gives a different, equally valid selection.
    • The scores are Tanimoto similarities on binary fingerprints. Count fingerprints cannot be stored in a packed index.
    • These tools rank fingerprints, not structures. Confirm a series or a near-duplicate that matters with an exact search; see Maximum common substructure and Substructure search.
